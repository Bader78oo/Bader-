# درس ٤ (مقترح) — ازرع واحصد الثمرة (اسم الكود: OmaniGarden)

هذي نسخة من وثيقة التنفيذ الأصلية (المكتوبة بمصطلحات Unity/Blender لنظارة Meta Quest 3 كتطبيق
APK مستقل)، بعد تحويلها بالكامل لنفس تقنيتنا الحالية: صفحة WebXR واحدة مبنية بـ A-Frame، تعمل في
متصفح النظارة مباشرة (بدون تثبيت APK)، بنفس محرك الدروس ١-٣ (نماذج Kit الإجرائية، سالم كدليل،
صوت Benji المسجل، بطاقات Canvas، نظام اللمس والتعرف على اليد). **التصميم التربوي والتسلسل والقياسات
كلها محفوظة كما هي من الوثيقة الأصلية** — اللي تغيّر هو فقط "كيف نبنيها" (الأداة)، مو "وش نبنيها".

## جدول التحويل: مصطلح Unity/Blender ← مكافئه عندنا

| في الوثيقة الأصلية | عندنا بدلاً عنه |
|---|---|
| Unity 6000.6 + URP + XR Interaction Toolkit + Meta XR Core SDK | A-Frame 1.7.1 (مُجهزة محليًا بالفعل في `public/vr/lib/`) — تعمل بمتصفح النظارة مباشرة، بدون أي تثبيت |
| ملف APK مستقل يُثبَّت على الجهاز | رابط ويب واحد (نفس أسلوب الدروس ١-٣)، يُنشر على GitHub Pages فورًا |
| Blender لنمذجة البيئة والنباتات | فئة `Kit` (بناء النماذج بأشكال بسيطة مدموجة بـ"سحب رسم واحد" لكل نموذج — نفس أسلوب كل نماذج الدروس السابقة) |
| Poly Haven / Sketchfab / BlenderKit (تحميل أصول جاهزة) | لا تحميل أصول خارجية إطلاقًا — كل شيء يُبنى بالكود وقت التحميل (خامات Canvas مرسومة برمجيًا، نفس تقنية عمامة وثوب سالم) |
| إضافات modular_tree / sapling_tree_gen / Geometry Nodes | دوال بناء إجرائية مكافئة بالكود (نفس أسلوب نخلة الدرس الثاني `MODELS.palm`) |
| ميزانية المثلثات (400/2000/6000/250 مثلث) وGPU Instancing | غير منطبقة بنفس الشكل؛ هدفنا المكافئ هو "سحبة رسم واحدة لكل نموذج" (مجموعة Kit مدموجة) — نفس قيد الأداء بروح مختلفة تناسب WebXR |
| Guide_OmaniBoy.fbx مع 5 مقاطع حركة (Animation Clips) | شخصية **سالم** نفسها (نفس الدليل بجميع الدروس، حفاظًا على الاستمرارية) أو شخصية جديدة بنفس أسلوب `buildSalem` — الحركة بتبديل "مزاج" برمجي (wave/cheer/think/point/idle) بدل مقاطع حركة جاهزة. **قرار يحتاج تأكيدك: سالم نفسه، أو دليل جديد بزي فلاح عماني؟** |
| Snap Turn فقط، بلا Teleport وبلا حركة مستمرة | **تغيير متعمد عن الدروس ١-٣**: تلك الدروس فيها مشي حر (تيليبورت بمنحنى) لأن بيئاتها كبيرة؛ هذا الدرس صغير (٦×٦م) فالطفل **ثابت بالمنتصف** ويدور بالخطوات فقط (`snap-turn` الموجود عندنا مسبقًا) — بدون تفعيل نظام المشي إطلاقًا |
| XR Interaction Toolkit (مسك، إفلات، أزرار) | نظامنا الحالي: `clickable`/`grabbable` + الليزر على يد المتحكم + تتبع اليد العاري (نقطة قريبة + مؤشر نظر للأبعد) — نفس أدوات الدروس ١-٣ |
| 5 أيام، 1500 ريال عماني (تقدير تطوير Unity) | غير منطبق؛ هذا تقدير لمسار Unity منفصل. مسار الويب عندنا أسرع تاريخيًا (كل درس من ١-٣ بُني وجُرِّب ونُشر خلال جلسة واحدة) — **سأعطيك تقدير وقت فعلي بعد ما تأكد لي نطاق الدرس** |
| ملف JSON للمعلومات العلمية المعتمدة من العميل | نفس أسلوبنا الحالي تمامًا: `content.js` (خط `LESSON.lines` + بيانات المحاصيل) — جاهز لمراجعتك قبل التسجيل الصوتي |

## 1. الفكرة (محفوظة كما هي)

الطفل يدخل مشتلًا عمانيًا صغيرًا ويزرع محصولًا من البذرة حتى القطف بيديه. الفئة العمرية ٧-١٥ سنة
(مبتدئ ٧-١٠، متقدم ١١-١٥) — **أوسع من نطاق الصف الأول** اللي بنيناه عليه الدروس ١-٣. هذا يعني
الدرس هذا لن يكون "الدرس ٤" بنفس تسلسل مادة العلوم للصف الأول، بل **تجربة مستقلة بمستويين**، تُعرض
في قائمة الدروس كعنصر خاص بيها (نفس ما عملنا مع "العرض التقني" — قسم منفصل، مو مرقّم مع ١-٣).
**قرار يحتاج تأكيدك إذا توافق على هذا التصنيف.**

قرارات المساحة الصغيرة محفوظة بالكامل: مشتل واحد مسوّر، لا تنقل بعيد، كل شيء بمستوى الطفل، إعادة
استخدام أنظمة مُختبرة بدل الكتابة من الصفر (عندنا: نظام الصوت، البطاقات، المسك، سالم، hub.js).

## 2. تصميم المشتل (القياسات محفوظة حرفيًا)

نقطة الأصل (٠,٠) = موقف الطفل عند البدء. كل القياسات بالمتر، تُبنى مباشرة بإحداثيات A-Frame
(بالضبط نفس أسلوب `polar(angle, radius)` المستخدم لتوزيع الحظائر بالدرس الثاني):

- جدران طينية ٦×٦م، ارتفاع ٢.٢م، قوس عماني بالجدار الخلفي (منظر فقط، بلا تفاعل).
- ٤ أحواض (طماطم، فراولة، تفاح، ليمون عماني) على قوس نصف قطره ١.٣م أمام الطفل، بزوايا
  −٦٠°، −٢٠°، +٢٠°، +٦٠°. حوض ١.٠×٠.٧م، ارتفاع ٠.٦م.
- رف البذور يسار (x=−1.5): ٤ برطمانات/أكياس بأسماء عربية.
- حامل الأدوات يسار-خلف: مجرفة، مرشّ ماء، برطمان حشرات.
- قناة الفلج يمين (x=+1.5)، طولها ٣م: ماء جارٍ (خامة UV متحركة، نفس أسلوب بِرَك الدرس الثاني)
  + بوابة + صنبور لتعبئة المرشّ.
- سلة القطف على طاولة قصيرة أمام الطفل.
- المرشد بالزاوية الأمامية اليمنى.
- غطاء ظل (شبكة + مقبض) فوق كل حوض.

الراحة والأمان (محفوظة): لا حركة كاميرا إلا عند الدخول (`blink()` الموجود عندنا للتعتيم القصير بين
المراحل)، وضع جلوس (الأحواض ٠.٤٥م بدل ٠.٦م)، الأداة التي تسقط ترجع لمكانها (نفس نمط "الصغير الضائع"
بالدرس الثاني اللي يرجع تلقائيًا)، لوحة التعليمات على بعد ١.٦م (نفس `showPanel`/`frontOf`)، إضاءة
نهارية فقط، بلا أصوات عالية مفاجئة.

## 3. سيناريو اللعب (آلة الحالات محفوظة بالكامل)

نفس التسلسل تمامًا، كل حالة = دالة `mode` عندنا (بالضبط نفس بنية الدروس ١-٣):

1. **المقدمة** — بانر ترحيب + كلام المرشد (نفس `intro()`)، تنتهي بالنظر للمرشد أو بعد ١٢ ثانية.
2. **اختيار البذرة** — لمس برطمان من الرف (`clickable`)؛ بذرة لا تناسب الحوض ترجع تلقائيًا بتنبيه لطيف.
3. **تجهيز التربة** — حفر بحركة لأسفل بالمجرفة (`grabbable` + قياس عمق الحركة)؛ تُقبل الحفرة من ٨سم.
4. **الزرع** — وضع البذرة + تغطية بثلاث دفعات (ثلاث نقرات/حركات) تحوّل الحفرة لكومة تربة.
5. **العناية** — ملء المرشّ من الفلج والسقي مع مراقبة مقياس رطوبة (HUD نفس `setHud`)، فتح/غلق غطاء
   الظل، التقاط الآفات بالبرطمان، الإفراط بالماء يُذبل النبتة مع تنبيه.
6. **النمو** — كل عناية صحيحة تُقدّم "يومًا" (ساعة شمس تدور، شبيه بزر الوقت بالدرس الثاني):
   بذرة ← نبتة ← نبات ← ثمار. لا يتقدم النمو إلا بإجراء صحيح.
7. **القطف** — قطف الثمرة الناضجة فقط (تبديل مادة/لون الثمرة من أخضر لناضج)؛ الثمرة الخضراء تُظهر
   "لم تنضج بعد".
8. **الأسئلة** — ٣ أسئلة بصرية، لمس الإجابة من لوحتين (بالضبط نفس محرك الاختبار بالدرس الثالث، بس
   بمحتوى زراعي).
9. **الملخص** — نجوم + شارات + رسالة ختامية + "إعادة التجربة" (نفس `summary()`).

### المستويان (محفوظان بالكامل، تُفعَّلان بمتغيّر `level` بسيط)

| | مبتدئ (٧-١٠) | متقدم (١١-١٥) |
|---|---|---|
| الإرشاد | توهّج + تلميح بعد ١٤ث + مساعدة تلقائية بعد ٤٠ث | تلميح فقط بعد ٢٥ث، بلا مساعدة تلقائية |
| المحاصيل | محصول واحد | محصولان |
| الرطوبة | نطاق واسع ٤٠-٩٠٪ | نطاق ضيق ٥٥-٧٥٪ |
| الآفات | آفة واحدة بطيئة | آفتان + حدث "ظهيرة حارة" (سحب الظل خلال ٢٠ث) |
| المؤقت | بلا مؤقت | ١٠ دقائق، بلا عقوبة قاسية |

### النقاط (محفوظة بالكامل)
على الإجراء الصحيح لا على كثرة الثمار: عمق الحفرة، تغطية البذرة، الرطوبة ضمن النطاق، إزالة الآفة
بوقتها، القطف عند النضج، الإجابة الصحيحة. ٣ نجوم عند ٥٠٪/٧٥٪/٩٠٪ (نفس بنية `{type:'stars'}` الجاهزة
بمحرك البطاقات). ٣ شارات: مزارع صغير، سقّاء الفلج، حارس النبات (تُحفظ عبر `hub.js` كبيانات اكتشاف،
نفس دفتر المغامرات المشترك بين كل الدروس).

## 4. المحاصيل ومراحل النمو

٤ محاصيل × ٣ مراحل نمو + ثمرة بمادتين (أخضر/ناضج) — تُبنى كـ`MODELS` إجرائية جديدة بنفس فئة `Kit`
(بالضبط نفس نمط نباتات/أشجار الدروس السابقة). **المعلومات العلمية الدقيقة (خصوصًا اسم الليمون
العماني وطريقة زراعته) تبقى بانتظار اعتمادك قبل ما تُكتب بـ`content.js` أو تُسجَّل صوتيًا** — نفس
التزامنا بعدم اختلاق معلومات زراعية غير معتمدة.

## 5. ما الذي يسقط من الوثيقة الأصلية (لأنه خاص بمسار Unity/Blender فقط)

- كل فقرة "الأصول" (P0/P1/P2، ميزانيات المثلثات، GPU Instancing، Poly Haven/Sketchfab/BlenderKit،
  إضافات Blender) — لا ينطبق؛ كل الأصول تُبنى بالكود مباشرة، بلا ملفات خارجية تُحمَّل.
- ملف Guide_OmaniBoy.fbx ومقاطع حركته الخمس — يُستبدل بشخصية مبنية بالكود (سالم أو دليل جديد).
- الجدول الزمني والتكلفة (٥ أيام / ١٥٠٠ ريال) — تقدير خاص بمسار Unity منفصل تمامًا.

## الأسئلة المفتوحة التي أحتاج إجابتك عليها قبل البدء

1. **الدليل**: سالم نفسه (استمرارية مع الدروس ١-٣ ودفتر المغامرات المشترك)، أو شخصية جديدة بزي فلاح عماني؟
2. **التصنيف بالموقع**: تجربة مستقلة بمستويين (مو مرقّمة ١-٢-٣-٤)، صح؟
3. **معلومات الليمون العماني** الدقيقة (الاسم العلمي/المحلي وخطوات زراعته) — تحتاج اعتمادك قبل الكتابة.
